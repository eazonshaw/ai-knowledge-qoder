## 正文

Zod, the TypeScript-first schema validation library created by Colin McDonnell, [released Zod 4.5](https://zod.dev/blog/zod-4-5) on August 28, 2026, introducing schema compilation, an order-of-magnitude cut in schema memory usage, and a batch of long-requested helpers. [Zod 4.6 followed on September 9](https://zod.dev/blog/zod-4-6), extending that work and fixing a recursive-schema memory regression. The major compilation and memory-footprint changes arrived in 4.5, which remains the focus here, but developers upgrading now should also account for the subsequent release.

The flagship addition is `z.compile()`, which turns any schema into a precompiled validator that parses the same data three to nine times faster. The compiled schema behaves exactly like the original, with no special rules. Importantly, [as McDonnell explains](https://x.com/colinhacks/status/2093725420462182512), compilation happens in-process rather than at build time, so there is no bundler plugin or codegen step to wire up.

Teams that want this applied everywhere can add `import "zod/compile"` at the top of an entry point, or run `node --import zod/compile app.js`, after which every schema is compiled lazily the first time it parses data.

By memoising bound methods instead of allocating them per instance, a bare `z.string()` now retains 784 bytes of heap rather than 7.5kb, a roughly [nine-fold reduction](https://zod.dev/blog/reducing-memory-footprint). `safeParse()` also skips stack-trace capture on failure, making invalid input about 7.5 times cheaper to reject. Alongside the speed, 4.5 restores `z.deepPartial()`, and adds `.exactPartial()`, `z.creditCard()`, `z.input()`/`z.output()`, cyclical data in recursive schemas, and eight new error locales.

The most directly relevant [4.6 addition](https://zod.dev/blog/zod-4-6) is `.validate()`, a boolean-only check that avoids constructing a parsed result or `ZodError` and can stop at the first issue. With compilation enabled, the release reports up to a 35-fold improvement over `.safeParse().success` on invalid input—not a general parsing speed-up or a replacement when transformed output or error details are needed.

Version 4.6 also adds property validation on class instances, six additional validation keywords in `z.fromJSONSchema()`, and `z.iban()`. For environments whose Content Security Policy blocks the `new Function` used by `z.compile()`, `z.withParser()` can install an externally generated parser; it does not generate that parser itself.

Importantly, 4.6 fixes a 4.5 regression that retained parsed data in recursive schemas and could cause out-of-memory failures.

Developer Mehul Mohan [described](https://x.com/mehulmpt/status/2100628504190877876) the roughly tenfold improvement on objects and arrays as "a real performance win".

On the [Moltar parseSafe benchmark](https://github.com/moltar/typescript-runtime-type-benchmarks) cited in the release, compiled Zod reaches 47.5M ops/sec, edging ahead of [Typia](https://typia.io/) at 45.3M and leaving [Valibot](https://valibot.dev/) (1.8M) and [ArkType](https://arktype.io/) (152k) far behind, a notable turn given ArkType has long marketed itself as many times faster than Zod. On the boolean-only assertion benchmark published with 4.5, Typia and ArkType led compiled Zod. Those figures remain a snapshot of that release, not a fresh comparison against 4.6's new `.validate()` path; the fastest option remains workload-dependent.

## 正文

The [release](https://medium.com/helidon/helidon-27-released-9ce206503e0a) of [Helidon 27](https://helidon.io/) is the very first that follows the Oracle [Tip & Tail Model of Library Development](https://openjdk.org/jeps/14) where the **Tip** adopts the latest Java technology and the **Tail** provides a more stable and secure baseline. Concurrent with the [release of JDK 27](https://www.infoq.com/news/2026/09/java27-released), changes include a restructure of the original programming models and introduce two new modules, [Helidon Messaging](https://helidon.io/docs/v4/mp/reactive-messaging) and [Helidon Data JDBC](https://helidon.io/docs/core/v27/modules/data).

Helidon 27 serves as the Tip, meaning that: it aligns with JDK 27; adopts the latest Java features; and will continue to be updated under the current OpenJDK release cadence. Therefore, Helidon 28 will be available with the upcoming release of JDK 28 in March 2027.

[Helidon 4.5.5](https://github.com/helidon-io/helidon/releases/tag/4.5.5), still managed under the familiar Helidon semantic versioning, serves as the Tail, means that: it maintains Helidon 4.5 LTS on its JDK 21 baseline with support for JDK 25; prioritizes critical bugs, security fixes and carefully selected backports; and allows for a longer-lived production baseline for development teams.

Helidon 27 is maintained under the auspices of the [Java Verified Portfolio](https://www.oracle.com/java/technologies/downloads/jvp/) (JVP), an ecosystem of Oracle-supported technologies first [introduced at JavaOne 2026](https://blogs.oracle.com/java/announcing-jvp), It also includes [JavaFX 27](https://jdk.java.net/javafx27/), [Jipher 20](https://blogs.oracle.com/java/announcing-oracle-jipher-20-fips-140-3-cryptography-for-java) and the [Java Platform Extension Visual Studio Code](https://inside.java/2023/10/18/announcing-vscode-extension/)

Originally named J4C (Java for Cloud), Helidon was designed to be simple and fast, and originally contained two programming models: **Helidon SE** and **Helidon MP**. This release introduces the new [Helidon Core](https://helidon.io/docs/core/v27/get-started), replacing Helidon SE, with two new programming models: **Imperative** and **Declarative**. As the names imply, Imperative, similar to heritage Helidon SE, allows developers to create their applications using “plain old” Java without dependency injection or annotations. Declarative, on the other hand, provides developers the ability to use dependency injection and annotations that generate imperative code and wiring at build time.

[Helidon MicroProfile](https://github.com/helidon-io/helidon-microprofile/blob/main/README.md) replaces the heritage Helidon MP and has been moved into its own project. It will continue to support the specifications under [MicroProfile](https://microprofile.io/) and [Jakarta EE](https://jakarta.ee/) and follow the Helidon semantic versioning.

[Helidon SE Integrations](https://helidon.io/docs/v4/se/integrations) has also been moved to its own project and renamed as [Helidon Extensions](https://github.com/helidon-io/helidon-extensions/blob/main/README.md). Each extension will be independently maintained under their own release lifecycle.

**Helidon Messaging**, a new messaging layer that simplifies traditional messaging, avoids reactive APIs such as the [MicroProfile Reactive Messaging](https://github.com/microprofile/microprofile-reactive-messaging/blob/main/README.adoc) specification. Developers can use ordinary, blocking Java for interoperability with connector-neutral channels, such as Kafka, JMS or Apache Pulsar, that are bound through configuration and pluggable connectors.

**Helidon Data JDBC** provides a unified API for working with data repository queries that serve as an abstraction over traditional Object–Relational Mapping (ORM). This enables interfaces with query definitions to be translated into implementation classes at compile time. Helidon Data JDBC supports the [Jakarta Persistence](https://jakarta.ee/specifications/persistence/) specification and its corresponding implementations, [EclipseLink](https://eclipse.dev/eclipselink/) and [Hibernate ORM](https://hibernate.org/orm/).

[Introduced in September 2018](https://medium.com/helidon/helidon-takes-flight-fb7e9e390e9c), Helidon SE featured three core APIs to create a microservice -- a web server, configuration, and security -- for building microservices-based applications. Helidon MP implemented various MicroProfile specifications.

Helidon has evolved over the years with the Java community to include support for: GraalVM; Java Persistence Architecture (now Jakarta Persistence); Micronaut Data; Kotlin; MicroStream (now EclipseStore); and IntelliJ IDEA.

[Released in June 2020](https://medium.com/helidon/announcing-helidon-2-0-19c245f5488a), Helidon 2.0 introduced a web client (to complement the web server) and a database client in Helidon SE and a new [command line tool](https://helidon.io/docs/v4/cli) (CLI).

[Released in July 2022](https://medium.com/helidon/helidon-3-0-is-released-1bd2df1f999b), Helidon 3.0 delivered: JDK 17 as a minimal version; an implementation of MicroProfile 5.0 and selected Jakarta EE 9.1 specifications; support for [JEP 290, Filter Incoming Serialization Data](https://openjdk.org/jeps/290), such that deserialization is disabled by default; an updated Helidon SE routing API; a new [project starter](https://helidon.io/starter/27.0.0?step=1); and an updated CLI.

The original Helidon web server, based on [Netty](https://netty.io/), was available in the version 1.0 to 3.0 release trains. A new web server, codenamed [Helidon Níma](https://helidon.io/nima), was based on [JEP 444, Virtual Threads](https://openjdk.org/jeps/444), and introduced with the [release of Helidon 4.0](https://medium.com/helidon/helidon-4-is-released-a06756e1562a) in October 2023.

More details on these releases may be found in the release notes for [version 27.0.0](https://github.com/helidon-io/helidon/blob/27.0.0/CHANGELOG.md) and [version 4.5.5](https://github.com/helidon-io/helidon/blob/4.5.5/CHANGELOG.md).

## 正文

Airbnb has extended its open source Chronon feature platform with [Push Mode and Near Real Time (NRT) Model Transform](https://medium.com/airbnb-engineering/the-guest-journey-updated-in-real-time-extending-airbnbs-sequence-recommender-with-chronon-8f1582578553) to update sequence based recommendation embeddings within seconds of guest activity. The change reduced embedding staleness from nearly two days to less than a minute, with typical updates arriving within 10 to 30 seconds. Airbnb also reported a 1.67% improvement in offline NDCG and an approximately 0.33% increase in uncancelled bookings in online A/B testing.

The work builds on Airbnb’s JourneyFormer based sequence recommender, which uses a Transformer encoder to represent a guest’s booking, review and browsing history. Previously, the encoder ran as a daily batch job, generating embeddings that were stored in a low latency store. During a search, the ranking system retrieved the latest embedding and combined it with the live query, keeping the Transformer outside the latency sensitive serving path. However, activity occurring after the daily batch could remain absent from the embedding until the following run, with processing delays bringing effective staleness close to two days.

*Airbnb’s initial architecture showing the daily batch sequence encoder, embedding store and online ranking path. (Source : [Airbnb Blog Post](https://medium.com/airbnb-engineering/the-guest-journey-updated-in-real-time-extending-airbnbs-sequence-recommender-with-chronon-8f1582578553))*

Airbnb addressed the freshness problem by adding two capabilities to [Chronon](https://chronon.ai/). Push Mode causes a streaming job to publish a notification when a feature value is committed, allowing downstream processing to react to updated guest activity rather than polling or waiting for a scheduled job. NRT Model Transform allows an already deployed model to run inside that streaming pipeline. Airbnb uses the same Transformer sequence encoder for the near real time path, avoiding a separate inference implementation for the streaming workflow.

The resulting pipeline captures events such as searches and listing views, combines them with the guest’s existing short and long-term sequence data, and triggers model inference when the updated feature state is available. The generated embedding is then written to the same low-latency store used by the batch system. Consequently, the online ranking path remains largely unchanged while the representation it retrieves becomes more current.

[Pengyu Hou](https://www.linkedin.com/in/pengyuhou/), Senior Software Engineer, Infrastructure at Airbnb, described the platform change as addressing the gap between event-driven data and model inference:

> NRT Model Transform lets Chronon call an already deployed model ... directly from within the streaming flow.

The approach follows a broader feature serving pattern in which predictions can be updated when underlying features change rather than computed on every user request. Feast, another open-source feature platform, documents cached prediction architectures where inference is triggered by feature updates, trading additional writes and pipeline complexity for lower serving latency. Chronon instead integrates streaming computation and model transformation into its feature platform and emphasizes consistency between offline and online computation.

Airbnb has contributed Push Mode and NRT Model Transform to the public Chronon [repository](https://github.com/airbnb/chronon/). Chronon supports both batch and streaming computation and provides online feature serving designed to maintain consistency between training and production inference.

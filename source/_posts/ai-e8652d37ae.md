## 正文

Fortanix has [announced](https://www.fortanix.com/company/pr/2026/10/fortanix-announces-confidential-ai-for-enterprise-grade-kubernetes-workloads-on-cncf-confidential-containers-coco) support for Confidential Containers in its Confidential AI platform. The integration connects Kubernetes workload attestation to encryption-key release, so workloads that meet security policy can decrypt models and sensitive data inside hardware-based trusted execution environments (TEEs).

[Confidential Containers](https://www.cncf.io/projects/confidential-containers/) (CoCo), a Cloud Native Computing Foundation project, runs Kubernetes pods inside confidential virtual machines backed by hardware-based trusted execution environments (TEEs). Unlike ordinary containers, whose isolation depends largely on the host operating system, confidential VMs use hardware protections to encrypt memory and restrict access to the workload while it runs. This helps protect data in use, not just data at rest or in transit, and can let teams run sensitive workloads on shared infrastructure. Those protections still depend on trusting the guest software and configuring attestation and key release correctly.

Fortanix's [technical overview](https://www.fortanix.com/blog/confidential-ai-at-container-speed) describes plugins connecting CoCo workloads to two services: Confidential Computing Manager (CCM), which verifies the environment, and Data Security Manager (DSM), which releases keys only to environments CCM has verified. The company says CCM can attest the processor and graphics processing unit (GPU) together, a check that depends on configuration.

CoCo moves image pulling and unpacking into the confidential guest. Its Attestation Agent collects hardware evidence, and its Confidential Data Hub obtains secrets after verification. In Fortanix's described workflow, keys stay in DSM if attestation fails, so the workload cannot decrypt protected models or data.

Fortanix chief product officer Anuj Jaiswal said in the announcement: "With attestation and key management in one platform, teams can adopt standard CoCo without building the trust layer themselves." Fortanix says CCM and DSM run clustered, with 24x7 support, as a hosted service, on-premises or air-gapped.

Fortanix's [Intel TDX deployment guide](https://support.fortanix.com/docs/deploy-confidential-container-coco-workloads-on-intel-tdx-platform) offers two GPU settings: `Required` makes CCM validate GPU evidence through NVIDIA's attestation service; `Ignored` checks only that evidence is present and disregards the result. The guide also notes that the Fortanix CoCo Helm chart does not configure host firmware or kernel settings, which must be completed beforehand.

Attestation and conditional secret delivery already exist in CoCo's open-source [Trustee](https://confidentialcontainers.org/docs/attestation/architecture) components. Trustee separates evidence appraisal from resource authorisation. Its attestation service compares platform claims with reference values, then its Key Broker Service applies a user-defined policy before releasing secrets from local storage, a plugin or an external key store. A successful attestation still requires that policy to authorise the request. Trustee also accepts GPU evidence bound to the processor's attestation report.

Microsoft's [Azure Secure Key Release](https://learn.microsoft.com/en-us/azure/confidential-computing/concept-skr-attestation) offers a managed alternative in Key Vault Premium and Managed HSM, integrated with Azure Attestation. It releases exportable keys, not secrets or certificates.

The pod's guest kernel and helper processes sit inside the trust boundary, so teams must trust them too. CoCo's [trust model](https://confidentialcontainers.org/docs/architecture/trust-model/trust-model) explains that hardware measurements usually cover the guest environment, with container verification forming a separate stage. It also warns that an enclave application can still expose a dangerous external interface and excludes denial-of-service protection and hardware side channels. Attestation does not establish that an AI application handles data safely.

Fortanix says CoCo support is available now, and its deployment guide documents installing the Fortanix CoCo Helm chart. The announcement also says Fortanix is developing open-source plugins for CoCo, without naming repositories or versions. CCM's [17 September release notes](https://support.fortanix.com/docs/5-0-ccm-patch-1-september-17-2026) added CoCo application registration for AMD Secure Encrypted Virtualization-Secure Nested Paging (SEV-SNP) and Intel Trust Domain Extensions (TDX).

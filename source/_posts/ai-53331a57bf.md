JDK 28 的[早期访问构建](https://jdk.java.net/28/) [Build 14](https://github.com/openjdk/jdk/releases/tag/jdk-28%2B14) 发布，它是 Build 13 的[升级](https://github.com/openjdk/jdk/compare/jdk-28%2B13...jdk-28%2B14)，修复了各种[问题](https://bugs.openjdk.org/issues/?jql=project%20%3D%20JDK%20AND%20fixversion%20%3D%2028%20and%20%22resolved%20in%20build%22%20%3D%20b14%20order%20by%20component%2C%20subcomponent)。要了解关于这个构建的更多细节，请参阅[发布说明](https://jdk.java.net/28/release-notes)。

#### TornadoVM

[TornadoVM](https://www.tornadovm.org/) 6.0.0 [发布](https://www.tornadovm.org/blogs/tornadovm-6-0-0-zero-jni-faster-runtime)，带来 Bug 修复、文档改进、依赖项升级以及以下新功能：在后端和库任务中，完全用更现代的“[外部函数与内存 API](https://openjdk.org/jeps/454) ”取代了 [Java 本机接口](https://docs.oracle.com/en/java/javase/26/docs/specs/jni/index.html)（JNI）； 移除了实验性的 [JVM 编译器接口](https://docs.oracle.com/en/graalvm/enterprise/20/docs/reference-manual/compiler/#graalvm-compiler)（JVMCI），转而“通过反射 + ASM + Unsafe 层获取所有编译器元数据，所有受支持的 JDK（21、25、26、27）都会将此作为唯一的统一路径”；扩展了 [CUDA 后端](https://www.tornadovm.org/cuda-for-java)。有关该版本的更多详细信息，请参阅[发布说明](https://github.com/beehive-lab/TornadoVM/releases/tag/v6.0.0)。InfoQ 随后将发布一篇更详细的新闻报道。

#### Micronaut

Micronaut 基金会[发布](https://micronaut.io/2026/08/31/micronaut-framework-5-1-3/)了基于 [Micronaut Core 5.1.13](https://github.com/micronaut-projects/micronaut-core/releases/tag/v5.1.13) 的 [Micronaut Framework](https://micronaut.io/) 5.1.3 版本。该版本对以下模块进行了补丁更新：[Micronaut SQL Libraries](https://micronaut-projects.github.io/micronaut-sql/latest/guide/)、[Micronaut Micrometer](https://micronaut-projects.github.io/micronaut-micrometer/latest/guide/)、[Micronaut OpenAPI/Swagger](https://micronaut-projects.github.io/micronaut-openapi/latest/guide/)、[Micronaut OpenSearch](https://micronaut-projects.github.io/micronaut-opensearch/latest/guide/)、[Micronaut Email](https://micronaut-projects.github.io/micronaut-email/latest/guide/)、[Micronaut Reactor](https://micronaut-projects.github.io/micronaut-reactor/latest/guide/)、[Micronaut Data](https://micronaut-projects.github.io/micronaut-data/latest/guide/) 以及 [Micronaut AWS](https://micronaut-projects.github.io/micronaut-aws/latest/guide/)。要了解有关该版本的更多详细信息，请参阅[发布说明](https://github.com/micronaut-projects/micronaut-platform/releases/tag/v5.1.3)。

#### GraalVM Development Kit

Oracle Labs 发布 [Graal Development Kit](https://graal.cloud/gdk/)（GDK）5.1.3 版本。该版本与前文介绍的 Micronaut 5.1.3 保持了兼容。在使用 [GDK Launcher](https://graal.cloud/gdk/launcher/?advanced=true) 和 [GDK CLI](https://graal.cloud/gdk/get-started/installing-gdk-cli/) 创建应用时，该版本支持通过 JDK 25 生成和构建 GDK 应用。Graal Development Kit for Micronaut（前身为 [Graal Cloud Native](https://blogs.oracle.com/java/post/announcing-graal-development-kit-437)）提供了一套精选的 Micronaut 框架模块，可以简化云应用程序的开发。要了解有关该版本的更多详细信息，请参阅[发布说明](https://github.com/oracle/graal-dev-kit/releases/tag/5.1.3)。

#### JReleaser

[JReleaser](https://jreleaser.org/) 1.26.0 [发布](https://andresalmiray.com/jreleaser-1-26-0-has-been-released/)，带来 Bug 修复、文档改进、依赖项升级以及以下新功能：通过在生成的 snapcraft.yml 文件中添加 platforms 节点，增强对 [Snapcraft](https://snapcraft.io/) 的支持；弃用 [SnapPackager](https://github.com/jreleaser/jreleaser/blob/main/core/jreleaser-model-impl/src/main/java/org/jreleaser/model/internal/packagers/SnapPackager.java) 类中定义的 runOn() 方法，并建议改用 buildFor() 方法； 新增一个选项，可以跳过 JBang 打包器存储库标签设置，从而解决 JBang 标签可能出现错误的问题。要了解有关该版本的更多详细信息，请参阅[发布说明](https://github.com/jreleaser/jreleaser/releases/tag/v1.26.0)。

#### LangChain4j

[LangChain4j](https://github.com/langchain4j) 1.20.0 正式发布（连同第 30 个测试版），提供了 Bug 修复、文档改进、依赖项升级以及以下新功能：实验性支持非阻塞和响应式模式；针对整个交互调用单个线程的 AI 服务方法，现在改为返回 [CompletableFuture](https://docs.oracle.com/en/java/javase/26/docs/api/java.base/java/util/concurrent/CompletableFuture.html) 和 [Flow.Publisher](https://docs.oracle.com/en/java/javase/26/docs/api/java.base/java/util/concurrent/Flow.Publisher.html)；新增针对 Jackson 3 JSON SPI 的可选支持。要了解有关该版本的更多详细信息，请参阅[发布说明](https://github.com/langchain4j/langchain4j/releases/tag/1.20.0)。

#### Java Operator SDK

[Java Operator SDK](https://javaoperatorsdk.io/) 5.6.0 [发布](https://javaoperatorsdk.io/blog/2026/09/02/version-5.6-released/)，带来了以下值得注意的变更：新增 [InformerPool](https://github.com/operator-framework/java-operator-sdk/blob/main/operator-framework-core/src/main/java/io/javaoperatorsdk/operator/processing/event/source/informer/pool/InformerPool.java) 接口，控制器和事件源现在共享 Informer，而非每个事件源各自拥有一个 Informer；此外，[EventRecorder](https://github.com/operator-framework/java-operator-sdk/blob/main/operator-framework-core/src/main/java/io/javaoperatorsdk/operator/api/event/EventRecorder.java) 接口的配置方式也发生了变化，从原有的 [RegisteredController](https://github.com/operator-framework/java-operator-sdk/blob/main/operator-framework-core/src/main/java/io/javaoperatorsdk/operator/RegisteredController.java) 接口改为使用 [ConfigurationService](https://github.com/operator-framework/java-operator-sdk/blob/main/operator-framework-core/src/main/java/io/javaoperatorsdk/operator/api/config/ConfigurationService.java) 接口中定义的 eventRecorder() 方法。要了解有关该版本的更多详细信息，请参阅[发布说明](https://github.com/operator-framework/java-operator-sdk/releases/tag/v5.6.0)。

#### JHipster

[JHipster](https://www.jhipster.tech/) 9.3.0 [发布](https://x.com/jhipster/status/2094210955639149004)，带来 Bug 修复、依赖项升级以及以下新功能：全面支持 Spring Boot 4、Jackson 3 和 Angular 22；响应式应用程序现在使用 [Vite](https://vite.dev/) 构建；在使用 Testcontainers 进行集成测试时，统一使用 Spring Boot 的 [@ServiceConnection](https://docs.spring.io/spring-boot/api/java/org/springframework/boot/testcontainers/service/connection/ServiceConnection.html) 注解。要了解有关该版本的更多详细信息，请参阅[发布说明](https://github.com/jhipster/generator-jhipster/releases/tag/v9.3.0)。

#### Kotlin Toolchain

JetBrains 团队[发布](https://blog.jetbrains.com/kotlin/2026/09/kotlin-toolchain-0-12-multiplatform-library-publishing-wasm-apps-and-more/) [Kotlin Toolchain](https://github.com/JetBrains/kotlin-toolchain/blob/main/README.md) 0.12.0。该工具链是进入 Kotlin 编程语言的统一入口。除了 Bug 修复和依赖项升级外，还包括以下新功能：扩展已发布的 Kotlin 库（最初仅限于 JVM 库），现在已涵盖多平台库；支持使用 kotlin run 命令执行 Wasm 应用；改进终端 UI 和 IDE 。要了解有关该版本的更多详细信息（包括破坏性变更），请参阅[发布说明](https://github.com/JetBrains/kotlin-toolchain/releases/tag/v0.12.0)。

#### Yupiik Fusion

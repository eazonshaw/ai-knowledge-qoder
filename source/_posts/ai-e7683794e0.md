This week's Java roundup for September 28th, 2026, features news highlighting: the GA releases of JobRunr 9.0 and OpenXava 8.0; point releases for Quarkus, Micronaut, LangChain4j, Eclipse JNoSQL; ADK for Java and ADK for Kotlin; and introducing Lathe, a new Java language server.

#### OpenJDK

JEP 544, [Ahead-of-Time Code Compilation](https://openjdk.org/jeps/544), has been [elevated](https://mail.openjdk.org/archives/list/jdk-dev@openjdk.org/thread/KAQGAGMSCWSWWTE6MJ4M26NU4NJ37FNJ/) from **Proposed to Target** to **Targeted** for JDK 28. This JEP proposes to improve application startup and warmup time such that it is instantly available with optimized native code when the HotSpot JVM starts. This enables applications to achieve peak performance more quickly and to sustain peak performance.

[Build 18](https://github.com/openjdk/jdk/releases/tag/jdk-28%2B18) of the JDK 28 [early-access builds](https://jdk.java.net/28/) was made available this past week featuring [updates](https://github.com/openjdk/jdk/compare/jdk-28%2B17...jdk-28%2B18) from Build 17 that include fixes for various [issues](https://bugs.openjdk.org/issues/?jql=project%20%3D%20JDK%20AND%20fixversion%20%3D%2028%20and%20%22resolved%20in%20build%22%20%3D%20b18%20order%20by%20component%2C%20subcomponent). More details on this release may be found in the [release notes](https://jdk.java.net/28/release-notes).

For [JDK 28](https://openjdk.org/projects/jdk/28/), developers are encouraged to report bugs via the [Java Bug Database](https://bugreport.java.com/bugreport/).

#### Jakarta EE

In his weekly [Hashtag Jakarta EE](https://www.agilejava.eu/) blog, [Ivar Grimstad](https://se.linkedin.com/in/ivargrimstad), Jakarta EE Developer Advocate at the Eclipse Foundation, provided an [update](https://www.agilejava.eu/2026/10/04/hashtag-jakarta-ee-353/) on Jakarta EE 12, writing:

> For Jakarta EE 12, the vote for including [Jakarta Authorization](https://jakarta.ee/specifications/authorization/) in [Jakarta EE Web Profile](https://jakarta.ee/specifications/webprofile/) is ongoing. It makes perfect sense to group it together with the other security specifications there. On request from the steering committee, the timeline for Jakarta EE 12 was discussed and firmed up in the platform call this week. The timeline for Jakarta EE 12 will look like this:
> 
> -   December 1 - Jakarta EE 12 Core Profile
> -   March 31 - Jakarta EE 12 Web Profile
> -   May 15 - Jakarta EE 12 Platform
> 
> One specification I, personally, really want to see included in [Jakarta EE 12 Web Profile](https://jakarta.ee/specifications/webprofile/12/) is [Jakarta NoSQL](https://jakarta.ee/specifications/nosql/1.1/). Simplifying and standardizing access to NoSQL datastores is a great feature when integrating artificial intelligence in enterprise applications. Particularly, support for vector databases for RAG is something that will be very useful. If you agree with me, or have an opinion about including Jakarta NoSQL in Jakarta EE 12, please do let us know on the mailing list or in the platform calls. The voice of the community matters!

[Eclipse JNoSQL](https://www.jnosql.org/), the compatible implementation of Jakarta NoSQL was recently elevated from an incubating project to an Eclipse Enterprise for Java (EE4J) project. It has been an Eclipse project since 2017 and has been included in [Eclipse GlassFish](https://glassfish.org/) since Jakarta EE 11 as part of support for [Jakarta Data](https://jakarta.ee/specifications/data/).

#### LangChain4j

The *formal release* (along with the *thirty-first beta release*) of [LangChain4j](https://github.com/langchain4j) 1.21.0 delivers bug fixes, dependency upgrades and introduces new, experimental decision models. This includes a new API consisting of the **`[DecisionModel](https://github.com/langchain4j/langchain4j/blob/main/langchain4j-core/src/main/java/dev/langchain4j/model/decision/DecisionModel.java)`** interface, and **`[DecisionServices](https://github.com/langchain4j/langchain4j/blob/main/langchain4j/src/main/java/dev/langchain4j/service/decision/DecisionServices.java)`**, **`[RoutingChatModel](https://github.com/langchain4j/langchain4j/blob/main/langchain4j-core/src/main/java/dev/langchain4j/model/chat/router/RoutingChatModel.java)`** and **`[DecisionRouterPlanner](https://github.com/langchain4j/langchain4j/blob/main/langchain4j-agentic-patterns/src/main/java/dev/langchain4j/agentic/patterns/decisionrouter/DecisionRouterPlanner.java)`** classes. #### Google Agent Development Kit

#### Lathe

[Alexey Gavrilov](https://www.linkedin.com/in/alexey-gavrilov-62222b2/), Senior Software Engineer at Telenor Linx, has [introduced](https://foojay.io/today/lathe-a-java-language-server-from-your-maven-build/) a new Java language server, [Lathe](https://github.com/ag-libs/lathe/blob/main/README.md), an implementation of the [Language Server Protocol](https://langserver.org/) (LSP). Lathe eliminates the difficulties with traditional project import and classpath or module-path configuration. It works in any editor compatible with LSP and its model comes from a Maven build such that everything remains synchronized. Lathe ships with a [Neovim](https://neovim.io/) client and an MCP server for AI coding agents. The latest release, available this past week, is [version 0.1.14](https://github.com/ag-libs/lathe/releases/tag/v0.1.14).

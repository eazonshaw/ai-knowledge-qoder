## 正文

最近，Cloudflare 通过 AI Gateway [推出](https://blog.cloudflare.com/introducing-web-search-api/)了一款测试版的 Web Search API。该 API 可以通过 REST API 和 Cloudflare Workers 访问，提供统一的日志记录、访问控制和计费功能，并支持自带提供商密钥。

[该 API](https://developers.cloudflare.com/web-search/) 使 AI 代理能够从 Ceramic.ai、Exa 和 Linkup 实时获取网页搜索结果。它提供统一的接口，将搜索计费与 [AI Gateway](https://www.cloudflare.com/products/ai-gateway/) 集成，可以同时记录搜索请求和模型推理，并要求服务提供商遵守[经过验证的机器人要求](https://developers.cloudflare.com/bots/concepts/bot/verified-bots/?cf_page=introducing-web-search-api%2F)并返回来源链接。

Cloudflare 的 Web Search API 允许 AI 应用程序检索最新的网络内容，包括近期新闻、API 变更和技术文档，并在推理过程中将这些结果作为上下文提供给语言模型。Cloudflare 集团产品经理 [Michelle Chen](https://www.linkedin.com/in/mchenco/)、高级总监 [Sam Else](https://www.linkedin.com/in/samelse) 以及高级系统工程师 [Gabriel Massadas](https://x.com/G4brym) 解释了该公司正在努力解决的挑战：

> 当你使用一个代理，而且需要它实时抓取网页时，代理通常只是猜测该页面的 URL，然后调用工具通过 curl 进行抓取。这就是为什么你有时会看到网页抓取返回 404 未找到错误——这通常发生在代理猜错了 URL 时。可以想象，总是随机猜测 URL 并不是特别高效的做法。

应用程序和外部服务可以通过提供 AI Gateway 身份验证令牌，并在请求负载中指定搜索提供商，从而通过 REST 端点访问网络搜索功能，获得搜索结果。Chen、Else 和 Massadas 补充道：

> 网络搜索提供商所使用的爬虫必须符合 Cloudflare 在开发者文档中定义的“已验证机器人”的公开要求，而且网络搜索响应必须包含指向已爬取内容的链接。这些规则对于构建一个公平的互联网具有积极的意义，并且允许内容创作者自主决定如何处理自己的数据。

在 [Hacker News 上的一个热门帖](https://news.ycombinator.com/item?id=49963171)中，社区成员们讨论了搜索质量、数据保留限制，以及统一 API 相比现有替代方案是否具有实质性优势。[Simon Willison](https://www.linkedin.com/in/simonwillison/) 写道：

> 对于搜索 API，我的首要疑问是：它们是否允许你存储并重新发布从它那里获取的结果。如果我正在运行一个代理系统，却不被允许存储响应结果——或者提供“分享对话记录”按钮——那将是一个相当大的限制。而这个问题的答案，往往被深埋在服务条款的字里行间中。

Erato Labs 首席技术官兼联合创始人 [Maximilian Goisser](https://www.hobofan.com/) 指出：

> 我认为，对于已经使用 Cloudflare 的企业而言，它正逐渐成为值得信赖的主要云服务供应商（通常这类角色由 AWS、GCP 或 Azure 担任），企业的大部分云服务费用将通过该平台结算（因此无需重新提交采购流程）。

Cloudflare 表示将筛选出支持“零数据保留”的供应商，并按供应商的标价提供搜索服务，不额外加收费用。该公司计划为 AI Gateway 添加原生服务器工具，首先从 Web 搜索开始。在此之前，开发者可以使用 [Cloudflare Workers](https://www.cloudflare.com/products/workers/) 将 Web 搜索集成到其工作流中。

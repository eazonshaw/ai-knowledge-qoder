## 正文

During a recent InfoQ webinar titled "[AI in Production: What Breaks, What Works, and Who Approves It](https://www.infoq.com/news/2026/10/infoq-ai-webinar/)?", a panel of senior engineering practitioners met to dissect the real-world operational challenges of deploying agentic systems. The discussion was moderated by [Hien Luu](https://www.linkedin.com/in/hienluu) and featured [Zichuan Xiong](https://www.linkedin.com/in/zichuan-xiong-94aa3b13) and [Prem Chandrasekaran from ThoughtWorks](https://www.linkedin.com/in/premanandc), privacy specialist [Katharine Jarmul](https://de.linkedin.com/in/katharinejarmul), and financial AI practitioner [Lan Chu](https://nl.linkedin.com/in/lanchuhuong). Luu opened the session by noting three core drivers: AI fails differently from traditional software by generating convincing inaccuracies rather than crashing; coding agents are generating production code faster than humans can review; and sensitive data has new places to leak through prompts, context windows, and retrieved documents.

Xiong, Head of AI Ops for Managed Services at ThoughtWorks, highlighted the widespread issue of "*semantic drift*" in LLM pipelines. He described how text-to-SQL translation agents frequently flatten domain-specific concepts, such as treating "*member*" identically across sales and customer support domains, leading to subtle, hidden errors in downstream business analytics that pass standard tracing. Similarly, Chu recounted a critical failure caused by "*embedding drift*" in financial compliance systems. After deploying an agent to block prohibited investment advice based on vector similarity thresholds, an unannounced background update to the underlying embedding model altered the vector distance distribution. This caused severe false positive and false negative spikes in live traffic while all infrastructure health checks remained completely green. Additionally, Chandrasekaran highlighted how RAG pipelines can inadvertently retrieve sensitive documents, while Jarmul noted that models inherently memorize training data and can be used to de-anonymize information or expose API keys. Chandrasekaran also referenced the [GitSpawn](https://labs.cloudsecurityalliance.org/research/csa-research-note-ai-coding-agent-git-config-rce-20260904-cs/) vulnerability, showing how malicious repository configurations can execute unauthorized code during routine commands.

As coding assistants generate an increasingly massive volume of production code, conventional human code review processes face unsustainable bottlenecks. Chandrasekaran, Tech and Business Services Lead at ThoughtWorks, emphasized that line-by-line manual code reviews cannot scale alongside high-velocity agent outputs. Instead, engineering teams must automate tactical style and syntax checks within CI/CD pipelines, reserving human oversight strictly for high-level architecture, business intent, and non-functional requirements. Xiong added that teams must shift left to evaluate intent at the harness level before pull requests are generated. Chandrasekaran also highlighted the resurgence of [mutation testing](https://en.wikipedia.org/wiki/Mutation_testing) as an essential practice. By introducing deliberate code mutations, teams can verify whether automated test suites truly evaluate underlying logic or merely satisfy surface-level code coverage metrics. When evaluating agentic systems, Chu stressed that evals must be treated as permanent, living infrastructure rather than static pre-release checklists. Effective evaluation requires continuous online tracing at the span level, log filtering, and using LLMs to categorize failure patterns, enabling teams to feed production edge cases back into offline benchmark suites.

To address privacy and security risks, Jarmul cautioned against relying on prompt engineering for system defence. She advocated for systematic red teaming, continuous threat modeling, defining strict functional scopes for autonomous agents, and scaling observability to handle expanded event volumes. To limit the blast radius of autonomous agent actions, Chandrasekaran advised treating every AI agent like a new engineering hire. Organizations should grant agents distinct non-human identities, implement tiered access controls distinguishing read-only operations from reversible write actions, version third-party Model Context Protocol (MCP) dependencies, and strictly isolate API secrets outside the agent's runtime environment in sandboxes. Ultimately, while engineering, security, and privacy teams validate safety guardrails, deployment approval remains a strategic business decision.
